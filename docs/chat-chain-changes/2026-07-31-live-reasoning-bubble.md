feature: Keep the current live reasoning stable between run status and tools
impact: Reasoning-only streaming assistant output is shown in a stable live detail area between the thinking animation and tool strip instead of briefly creating transcript bubbles. The current segment grows from its first delta, stays frozen after it seals, and is replaced only when the next reasoning segment begins. Each tool boundary still starts a fresh assistant reasoning segment instead of accumulating later thinking in the first bubble. Completion output without a body delta is attached to the active reasoning message; only sealed reasoning-only replies whose reasoning moved to an adjacent tool are hidden, so reasoning-only terminal responses remain visible. Direct, Coding Agent response-stream, group-chat persistence, and foreground/background subagent streams all associate the active pre-tool reasoning segment with the matching tool call and reset the segment at the boundary. The subagent drawer now uses the exact same thinking component, DOM, and styles as single chat, including the frozen-current-reasoning model, live tool strip, and lack of a left-side reasoning rule. Raw subagent thinking entries never render as standalone messages, and all subagent reasoning stays out of transcript bubbles while the child run is active; after completion, it returns only on the owning assistant message or tool detail. Tool boundaries revoke provisional text ownership so the same reasoning segment is not duplicated on both. Subagent and background-task drawers clamp to their containing viewport from the first paint, including mobile layouts, so saved desktop widths cannot push them off-screen. The thinking animation and surrounding run toolbar remain visible for the full run lifecycle, including tool execution, and close only when the run or abort lifecycle ends.
